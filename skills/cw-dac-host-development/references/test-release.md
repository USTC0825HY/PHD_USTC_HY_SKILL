# 测试、发布与技能同步

## 按改动选择验证

先发现实际 Python/Tcl 与依赖，区分测试解释器和 GUI 打包解释器；历史 Anaconda pytest 或固定 Python312 路径只是线索，不是永久约束。

应用改动按影响执行：host 下 `python -m pytest tests -q`、项目根 `tclsh tcl/cw_test_server.tcl --selftest`、对应 DDS/manual/ILA Tcl 测试、适用的真实 Tk 进程内按钮冒烟。记录实际命令、运行时、数量、失败/跳过和未运行项，不复用历史成绩。

重点覆盖延迟、断线、重复 ID、结果未知不重发、取消/再次开始、单连接归属、普通 ADC 无 CW 核、多同名探针、部分导出和失败证据。定时 ILA 加入固定时点、超期跳过、成功完整轮次计数及属性恢复；手动操作区分发送与查询。Fake VISA/Mock ILA 不构成硬件验收。

纯技能/工程说明修订只要求结构、引用、事实和场景复核，不启动应用打包或硬件业务。MATLAB 分析或报告另走对应技能。

## 有应用发布任务时

1. 选择未占用的新 vN 目录，复制并调整 spec；用确认过的构建解释器 `python -m PyInstaller`。不覆盖旧包或运行中的 EXE/runtime，避免锁文件导致部分删除。
2. 按实际 source/import 依赖闭包打包，不只复制主 Tcl。逐项核对 unified_tasks、manual_control、ila_capture_v2、DDS 共享库、契约及 JSON/YAML 等目标能力所需文件；固定列表不能替代依赖检查。
3. 检查打包资源是否随当前源码更新，记录来源及逐文件 SHA-256；执行 EXE --self-check、包清单一致性与 ZIP 完整性检查。不要把当前源码已更新当作包内已更新。
4. 无 Python 改动且接口兼容已验证时，可在新版本目录更新 Tcl/配置并重打 ZIP；旧包仍保留。启动器选择、服务配套切换与回滚方式一并记录。
5. 包中运行日志/数据先列清单、确认来源再处理，不复制历史清单的删除命令。切换服务前确认旧任务结束；通用 ILA 的空闲传输关闭不能误用带 CW 输出释放副作用的旧 stop_server，按目标模式操作文档执行。

硬件验收仅在当前任务授权覆盖设备、范围和动作时进行，分别记录 GUI/JTAG、大 LTX、采集、取消、控制恢复与仪器关断；未测试写未验收。不能沿用旧任务的提交、推送或上板授权。

## 技能维护

工程 skills 为本技能权威源。按 MAINTENANCE.md 保存基线与目标备份，完成 quick_validate、引用/场景检查，再按白名单同步 Codex、ZCode 并逐文件核对 SHA。目标偏离基线则停止该文件并合并，不覆盖并行工作。保持名称、调用策略及 UI 元数据；旧引用可保留兼容入口。

稳定入口或长期状态变化才更新简短 MEMORY；本轮验证证据另存报告。Git 提交/推送须当前用户授权，不由技能维护自动触发。
