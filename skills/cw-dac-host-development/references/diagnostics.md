# 故障定位

取证顺序：目标源码/EXE 来源与清单 → 端口和进程 → Vivado Console → GUI 日志 → 会话/操作编号和阶段 → 设备、探针及文件证据。旧“已连接”标签不证明在线，33443 不证明具体版本。

- **10061 / 未监听**：source 完成不等于 READY；核对配套脚本和 start_server_bg。旧前台 vwait 与后台服务分开。不要强杀用户 Vivado。
- **busy / 单客户端占用**：检查活动任务、另一上位机和同步硬件调用；不新开第二套服务抢板。重载须等任务和硬件调用结束。
- **手动结果待确认**：保存操作编号，按 manual_result_v1 主动查询；发送、服务执行、物理输出三个状态分开。不恢复旧版自动 300ms 轮询来掩盖问题。
- **任务超时/迟到**：记录原阶段、预算、session_id/task_id，丢弃失步 socket/残留缓冲；同会话按协议查询，服务重启/记录缺失则未知。不重发 program/capture/control 猜测结果。
- **ILA 冻结/停止延迟**：先核对是否旧同步 wait；旧 v7 GUI 内嵌限制仍有效。新任务的同步上传/导出也可能等待返回；取消监视或 reset_hw_ila 不是停止证据。
- **设备/探针变化**：结束计划后重新枚举、核对完整核名/探针/深度。路径相同的外部重烧不能只凭属性识别；按当前模式重新加载服务和枚举。通用 ILA 不自动烧写或关联 LTX；需要硬件准备时另按任务授权处理。
- **CSV/同名信号**：核对完整路径、源进制、partial、样本数、哈希、completed 索引及原子清单；不能两端统一短名而合并不同层级。保留失败文件和已完成轮次。
- **GUI 回调失败**：进程内驱动真实按钮路径，拦截弹窗与硬件工厂，检查取消后再开始、迟到消息及资源释放；worker 只用主线程快照。

## 2018.3 与旧接口经验的适用范围

- Tcl 批处理硬件管理入口核实 open_hw/实际命令可用性；管道 stdin 的 Tcl REPL 不等于 GUI 事件循环测试。
- 器件列表为空时核对供电/JTAG/当前目标，重开或重连是硬件会话动作，不能在活动任务中盲目执行。断电后先确认实际固件身份，不把任何连接错误都诊断成必须重烧。
- VIO 写值按确切探针位宽格式化；读值依据该接口返回的进制解析，保留前导零字符串时避免 Tcl 八进制及非法 JSON 数值。不要将“某接口裸串为 HEX”推广到所有 CSV。
- 大整数换算检查 Tcl wide 与字段范围、Python 格式说明符及 1 位有符号归一化；用最小离线例验证，不能靠名称推断。
- LTX 关联属于 Vivado 会话；外部烧写后的重新关联按模式说明执行。观测别名可能被综合合并，RTL/LTX 名称须重新核对，不能从旧 mock 推断现板。
- 截图可能受窗口遮挡影响，不能用截图替代按钮路径与协议验证；诊断截图须核对实际目标窗口和主题。

内部 ILA/VIO 证据不证明模拟端口；SDG 输出关断、ADC/DAC 控制恢复和 ILA 取消分别报告。
