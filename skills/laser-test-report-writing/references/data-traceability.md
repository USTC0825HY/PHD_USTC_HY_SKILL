# 数据溯源附录（当前约定）

新建513/CW结果报告末尾设“附录：数据溯源表”；正文结果结构不增加管理性段落。表头深蓝白字，正文中性白底，不采用改焊行底纹。

固定七列：器件｜指标｜接口｜改焊状态｜源数据路径｜分析结果路径｜汇总文件/备注。旧“关键汇总文件”列名保留读取兼容，局部编辑按目标现有列处理。

## 路径与身份

使用 [513路径规则](../../hardware-evidence-report-sync/references/513-traceability.md)。引言说明选定主库根、其快照截止和目录版本；主库内经核验显示相对路径，库外保留绝对路径并注明原因。同格多路径用“；”分隔，每条独立核验。访问失败写待核验，不写成主库缺失。

器件、接口、日期、改焊状态必须来自明确记录。组合对象 ADG526_AD677 优先于 AD677 子串；批次、采集、处理日期分别存放。不得按路径第一个日期、run 日期或固定分界自动判改焊。同一文件哈希存在于两个板卡目录时保留来源争议，不能直接认为两次独立测量。

每个报告结果表行/图均能追到至少一个来源；同源图表可以共享附录行。旧数据仍有报告引用时保留其行，复测另列；不要把已失效/无引用的条目永久当作当前证据。

## 辅助生成

scripts/make_traceability_rows.py 保留 --paths/--paths-file/--out，兼容 --campaign，新增 --root、--mapping、--manifest。输出保持原七列及旧路径输入等旧字段，追加备注、采集/处理/批次日期和逐路径核验JSON；CSV是草稿，不直接编辑DOCX。

--manifest 接收CSV或JSON数组，每行用唯一 input_path 精确绑定输入，选填 device、indicator、interface、rework_status、acquisition_date、source_path、result_path、summary_file。先从对应结果包清单核实再提供这些字段；manifest是显式来源，不是猜测模板。原始结果清单不能无依据直接转换字段。

不根据相邻raw目录猜run来源；未提供来源清单时标待确认。汇总文件仅在实际存在时输出，不默认伪造“结果汇总.xlsx”。输入/映射/清单及主库保持只读；输出放任务区。

局部修改以 SKILL.md 的任务模式优先：保留未授权旧版式/旧附录缺项，只补充本次授权的溯源行，旧缺陷单列。
