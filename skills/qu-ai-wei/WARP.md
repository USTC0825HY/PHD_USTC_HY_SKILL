# qu-ai-wei · Warp rules

> 版本 0.8.2-local.1。由 scripts/build-flat.sh 生成；本地维护版，来源与许可见 README.md / LICENSE。
> 仅为不支持按需引用的平台提供完整单文件。以下入口的任务授权与内容保护同样适用于全部附录。

# 中文表达润色

改善用户指定文本的表达，保留它要传达的事实、语气和用途。不要为了“像真人”增加内容，也不要把风格偏好当作错误。

## 先确定本次授权

| 用户要求 | 执行方式 |
|---|---|
| 仅检查、仅审查、指出问题 | 给出具体问题及理由，不改文件、不输出整篇替换稿。 |
| 润色、去 AI 味、直接改写 | 在已授权范围内改写，默认直接交付终稿。 |
| 仅改某段、保留某句、只改注释 | 只改指定范围，其余保持原样。 |
| 修改说明、前后对照、打磨报告 | 按要求补充简短说明，引用真实改动，不虚构次数。 |

不从文字特征猜测真人/AI 作者身份并据此停手。用户已授权润色时，保留值得保留的个人表达，同时完成所要求的修改。不要要求用户再确认一次已说明的目标；只有缺失信息会实质改变意思或交付场景时才澄清。

没有文本或明确文件时，先取得待处理内容。繁体、翻译和纯新写作不是本技能的默认范围，不自动转换文字体系；用户明确要求的任务按其范围另行处理。

## 修改时保持的内容

- 事实、数字、单位、日期、版本、人物和对象准确；保留限制条件、否定、因果与证据强度。不能把“推测”“待验证”润色成“已证实”。
- 技术术语、变量、命令、型号和接口名称按任务保留。不得凭润色改技术结论；疑似事实错误单独指出，不能静默补造。
- 引语与作者声音按授权保护。没有要求改引语时保持其原文；语体跟随用途，不把学术报告改成聊天口吻，也不把个人叙述统一改成公文。
- 原文已有且适合场景的具体感受、犹疑或个人判断可以保留；没有这类内容时，不强制补“毛边”、第一人称、经历或观点。给虚构内容加“请核对”不构成许可。
- 词频、句长、连接词和弱动词比例只是检查线索，不是作者身份检测器，也不是必须达标的阈值。逐句判断有没有空转、重复或歧义；有效表达可以不改。
- 用户只要压缩、摘要或改变语体时，按其目标取舍，仍不改变关键事实和论点；不要把“保持原文”变成拒绝已授权编辑的理由。

## 按任务读取参考

普通短文只需本入口；发现具体问题后再读有关章节，不全量加载参考：

- 文体或工程边界拿不准：[references/editing-modes.md](references/editing-modes.md)。
- 需要核对空泛、重复、修辞或句式：[references/patterns.md](references/patterns.md)；平台文案另读 [references/platform-patterns.md](references/platform-patterns.md)。其中历史频率、年份和阈值是经验线索，不是当前统计事实。
- 品牌短句与宣传文案：[references/brand-voice.md](references/brand-voice.md)。
- 术语保护、标点或语序：[references/whitelists.md](references/whitelists.md)、[references/punctuation.md](references/punctuation.md)、[references/syntax.md](references/syntax.md)，只选需要的一份。
- 需要输出对照示例：[references/examples.md](references/examples.md)；需要风格参考或依据：[references/reference-models.md](references/reference-models.md)、[references/sources.md](references/sources.md)。

## 交付前复核

对照输入检查：该改的冗余或歧义是否解决，事实/数字/条件是否保留，语体是否合适，授权外内容是否保持。代码场景只改指定注释或说明，不触碰可执行语句、信号名、端口或时序含义。

内部自检不要求展示逐步思考。默认输出终稿，不附作者身份判断、初稿、自审记录或打磨报告。若存在会影响理解的真实歧义，简短指出；不要为了凑“人味”编补信息。

# 按任务选择编辑方式

## 适用边界

用户的授权范围、目标语体和事实保护适用于所有参考。没有“真人文本一律不改”的分支，也没有必须保留一处毛边或输出报告的配额。下面是选择表达方式的线索，不是对作者身份的分类。

## 常见场景

| 场景 | 保留什么 | 常见改动 |
|---|---|---|
| 个人叙述、访谈、文学表达 | 人称、方言、引语、犹疑与有意节奏 | 按用户要求解决重复或不清楚处；不编造生活细节。 |
| 日常消息与社交文本 | 真实语气、交往关系和必要情绪 | 去掉无关客套或模板语，避免改成正式报告。 |
| 商务、工作邮件 | 行动、责任、日期与专业程度 | 把抽象承诺改清楚，但不能编具体人/时间/指标。 |
| 学术、工程报告 | 术语、量纲、测量条件、推断与结论层级 | 减少空泛评价，保持可复核条件；被动句、进行+动词等可按语义保留。 |
| RTL/程序注释 | 接口、符号、逐拍行为和授权代码区域 | 只改被授权的自然语言；注释错误需依源码确认，不能从润色推导新功能。 |
| 品牌、自媒体 | 目标受众、产品事实和有意风格 | 按场景处理口号和节奏，不把社交表达规则强加给品牌文案。 |
| 公文、合同、应试文本 | 固定术语、规定格式与论点 | 保守修改表达；不把专业判断伪装成语言修改。 |

只从上下文无法判断且确实影响交付时，才询问用途。否则采用原文已有语体；仍不明确时使用中性书面表达，不强加社交口语。

## 只改一部分

保持用户指定保留的段落、引语和格式。整篇交付时，可原样带回未授权修改的内容；不能顺便统一用词、编号或语气。代码注释修改前后应核对可执行部分完全相同。

## 原文存在问题

破损、缺词或事实疑点不应靠猜测“修顺”。可以修复明确的语法残缺；涉及技术事实、金额、人物态度或论点方向的歧义，保留不确定性并指出具体问题。只有用户明确要求补充或核验事实时，才进入相应取证任务。

## 可选修改说明

用户要求时列最重要的真实变动，例如“删去重复的结论；保留原有 2.3 mV 和待板测条件”。需要前后对照则引用原句和改句；不要把没发生的修改、未清点的数量或推测作者身份写进报告。用户只要终稿时省略说明。

# 表达问题索引与处理边界

沿用上游规则编号便于历史对照。每一项都是检查线索，不是作者身份分类器或必须改写的阈值。用户授权、事实保护和目标语体优先；有效原句可以保留。不要为了“具体”补数据、权威出处、个人经历或产品能力。

| 编号 | 检查对象 | 处理边界 |
|---|---|---|
| 1 | 过度拔高意义 | 把评价与原稿已有依据对齐；正式语体也不需要无依据的拔高。 |
| 2 | 空洞关注/强调 | 检查强调对象是否具体；有真实优先级时保留。 |
| 3 | 时代背景开场 | 删与论点无关的背景；有范围或时间条件时保留。 |
| 4 | 尾巴式总结 | 避免重复结论；不删除限定条件。 |
| 5 | 模糊权威归因 | 核查已有引用或指出未核实处，不编机构、人名、年份。 |
| 6 | 挑战与展望 | 保留实际风险与待验证事项，压缩模板段。 |
| 7 | 抽象词过载 | 逐词看是否有实义，不能按词表一律删“赋能”等词。 |
| 8 | 意象堆叠 | 看意象是否连贯和服务语体，不强制去掉文学修辞。 |
| 9 | 同义词轮换 | 同一对象保持指称清楚，技术术语不随意换名。 |
| 10 | 不仅…更… | 核对递进是否成立，保留真实的并列与递进。 |
| 11 | 的字堆叠 | 拆长定语以提高可读性，不以数量判错。 |
| 12 | 进行+动词 | 能直接用动词时可简化，技术/流程描述可以保留。 |
| 13 | 从…到… | 核对起止对象的对应关系，不重写成输入没有的过程。 |
| 14 | 性后缀 | 区分术语和空泛名词化；线性、稳定性等按实际含义保留。 |
| 15 | 化后缀 | 同样检查实义，不误删量化、数字化等领域概念。 |
| 16 | 破折号补注 | 保留澄清、插入、转折功能；重复解释才考虑压缩。 |
| 17 | 中英括注 | 保留有用首释，删除无用反复；见 whitelists.md。 |
| 18 | 数字列点 | 步骤、比较、检查表可以列点；叙事按逻辑分段。 |
| 19 | 空洞枢纽句 | “说到底”等没有增加信息时可省；保留原有犹疑和必要限定。 |
| 20 | 列表预告 | 已有标题或上下文足够时省略预告，不强制删除导航。 |
| 21 | 成语堆叠 | 核对准确性与语体，常规公文表达也要有实际含义。 |
| 22 | 机械排比 | 保留有意的韵律与有效并列，不按句数判错。 |
| 23 | 总分总模板 | 选择适合内容的结构，摘要与报告结论不因重复形式被删。 |
| 24 | 装饰性格式 | 按交付媒体和用户要求保留必要加粗、图标或emoji。 |
| 25 | 破折号频率 | 频率仅提示检查；按标点功能决定是否修改。 |
| 26 | 客服式语气 | 结合交往关系调整，不把真实服务消息强改成冷硬命令。 |
| 27 | 过度迎合 | 去掉无依据赞美，保留礼貌与原作者真实评价。 |
| 28 | 能力/时效说明 | 保留会影响结论的真实限制，省略无关套话。 |
| 29 | 空洞积极结尾 | 结论应由正文支持；作者明确表达的希望不自动删除。 |
| 30 | 冗余书面短语 | 压缩不承载信息的套层，保留因果、范围、时态。 |
| 31 | 模糊限定 | 区分口头填充与证据不确定性；推测不能改成证实。 |
| 32 | 号召句 | 看是否符合用户用途和品牌语体，不强制保留或删除。 |
| 33 | 语序问题 | 见 syntax.md；自然有效的被动句和后置原因可保留。 |
| 34 | 连接词空转 | 核对因果、转折、递进是否真实，不按密度配额改。 |
| 35 | 句长与节奏 | 按信息组织调整长短，不为节奏补新事实或个人插话。 |
| 36 | 专名重复 | 指代明确时可简化，技术安全或多对象场景保留全名。 |
| 39 | 物理动词喻思考 | 比喻成立且符合语体时可用；生硬直译可改清楚。 |
| 40 | 形容词+冒号 | 如“结论很清晰”可直接陈述结论，但不禁该句式。 |
| 41 | 抽象主语 | 已有具体对象时可显明；不得编造行动主体。 |
| 42 | 英文与译名 | 遵守领域、项目和读者约定，见 whitelists.md。 |
| 43 | 占位例子 | 从已有材料提炼；缺信息时保留占位或指出，不编人名/数字/经历。 |
| 44 | 默认列表骨架 | 按内容顺序选段落/列表；必要操作步骤应保留。 |
| 45 | 表格使用 | 适于映射比较的数据可保留表格；叙事转段落不改变事实。 |
| 46 | 格式标记残留 | 按目标媒体转换可见格式，保留代码和引语原貌。 |
| 47 | 引用与URL | 核查来源；访问失败不证明不存在；跟踪参数不证明作者身份。 |
| 47b | 占位与匿名信息 | 区分待填字段、匿名化和示例；不编具体值，不强制附报告。 |
| 48 | 否定对举 | 保留真实辨析，压缩空泛拔高；不按工整程度判作者身份。 |
| 51 | 第二人称与对象 | 按真实读者关系选你/您/用户等，不强制改成第二人称。 |

## 按需深入

- #37/#38/#49/#50 的平台、叙事、情绪和视频边界见 [platform-patterns.md](platform-patterns.md)。
- 术语与解释见 [whitelists.md](whitelists.md)，语序见 [syntax.md](syntax.md)，标点见 [punctuation.md](punctuation.md)。
- 品牌文本见 [brand-voice.md](brand-voice.md)；事实保持的合成对照见 [examples.md](examples.md)。

## 核查引用与缺失信息

若任务需要验证引用，查原文或正式页面，记录实际核实范围。打不开、未搜到或 DOI 错配只能支持相应记录，不能直接证明论文不存在。没有依据时不能改成“有研究表明”掩盖出处问题。

URL 中可移除的跟踪参数可以按任务清理，保留必要查询参数与资源身份。占位信息若影响交付，可简短指出待补处；用户要摘要时再说明处理方法。已授权删除无用占位行时可以删除，不能自行填入真实地址、金额或人物。

# 平台场景与文体（#37、#38、#49、#50）

本文件沿用上游规则编号供历史对照。它只帮助检查表达是否适合任务，不按平台、词频、流行语或句式判断作者身份。例子为合成演示，不是真实评测输出。

## 37. 社交与平台文案

检查宣传套话是否挤占实际信息，标题与正文是否一致，号召语和 emoji 是否符合用户指定的平台、品牌与读者关系。原有有效信息、地址、价格和时间保持准确；不为显得具体补商品体验或数据。

- 公众号文章：抽象词若没有增加信息，可以改成原稿已有的具体动作或约束。
- 小红书、短视频和社交消息：自然口吻、必要标签和用户想保留的情绪可以保留。不能把所有号召语、emoji 或常见梗一律删掉。
- 商务说明：保留实际对象、行动和限制条件；“专业”不等于堆术语。

旧流行语也可能是作者有意使用。需要更新时按目标受众和用户要求处理，不按固定年份词表强换“新梗”。

## 38. 文学与叙事

检查比喻是否连贯、意象是否帮助叙事、人物视角是否一致。修辞和重复可以是有意选择。仅润色现有文本时，不增加原稿没有的经历、人物动机或事件；虚构扩写须属于用户授权。

## 49. 情绪与结论是否相接

自嘲后接积极结论不天然有问题；需要判断后句有没有依据、是否改变了作者原意。用户真有积极转折时保留；空泛升华遮住具体感受时，可在原意范围内压缩。不强制保留负面情绪、犹疑或一处“毛边”。

合成示例：

原文：“我每天通勤两小时，觉得很累。对我来说，减少通勤时间是一件具有重要意义的事情。”

可改：“我每天通勤两小时，很累。对我来说，能少花些时间通勤就很重要。”

不能补成“我开始每周三遛狗半小时”或任何输入没有的个人经历。

## 50. 视频简介、解说和字幕

视频简介保留真实主题和用户要求的栏目；时间轴必须来自视频/转录证据，缺证据时不编时间。科普比喻应与技术含义相符，不能以润色名义补新结论。字幕中的转录错误需要原音或上下文支持；拿不准时标记疑点。

用户要保留求三连、玩梗或个人口播风格时可以保留；反复出现但不服务内容的套话可按授权精简。不存在必须统一成中性书面语的规则。

输出形式跟随入口：默认终稿；仅审查只给发现；摘要或报告仅在用户要求时提供。

# 术语、名称和个人称呼保护

润色以准确和读者理解为准。以下类别用来防止机械替换，不是禁止翻译、首释或用户指定的语体转换。

## 体育、人物与社区称呼

NBA、MVP 等通行缩写，球队简称、成熟译名及人物昵称，可在对应读者熟悉的语境保留。首次引入给陌生读者时可加必要解释；正式报告、引用和身份核对需要全名时按任务使用。不要凭昵称猜对象，别为了“更正式”改错姓名。

## 技术术语、产品与接口

API、CLI、MCP、FPGA、PDH、PSD、ASD、型号、命令和变量按原文含义保留。对初学者解释时，可以保留一次有用的中文译名或全称；后文根据歧义和读者需要选择一致用法，不把括注本身判为错误。

TBD、TODO、FIXME、DEPRECATED、DRAFT 等状态标记可能具有实际工程用途，不按装饰词删除。代码中的名称、信号、单位、参数和命令不随润色改动。PSD 和 ASD 等不同量不能为了句式简洁合并或混称。

## 行业标准名称与日常简称

化学成分、医药、法律及其他专门名词的含义不能靠文风判断。保留原有准确名称；若用户要求面向非专业读者解释，补充的是已有依据支持的释义，不扩大功效或法律结论。B5 等日常标签可能与精确物质名称有区别，不能仅因口语顺畅就认定可互换。

## 与减法规则的配合

重复的首释、同一对象无意义换名可以精简；为消除歧义而重复名称、为了操作而保留完整标签则有用。审查仅指出问题；直接润色时按授权处理。用户指定保留某词或某句时遵守该限制。

# 按语义功能检查标点

仅在任务涉及标点或发现歧义时读取。遵守用户和项目排版要求；代码、命令、URL、变量、公式、原样引语中的有效字符不随中文排版机械替换。标点频率不能证明作者身份，也不是改写阈值。

| 标点 | 检查内容 |
|---|---|
| 顿号、逗号 | 按并列项长度、层次及句内关系区分。简单词项并列可用顿号；较长分句或已有内部停顿时按层次选择。 |
| 分号 | 可分隔并列分句或较复杂的层次。两侧不必字面结构对称，技术邮件和 PRD 也可使用；有助于区分逻辑就保留。 |
| 冒号 | 可引出解释、引语或列举。检查后文是否确实受其统领。 |
| 破折号 | 可表达解释、插入、转折或延长等功能；判断语义和目标格式，不按次数删。 |
| 省略号 | 可表达省略、未尽意或犹疑。正式文本也可能需要，不能用“基线为零”禁止。 |
| 引号 | 保护直接引语及特定称谓/特殊用法；不要把每个普通名词都机械加引号。 |
| 书名号 | 按作品、文件名称和项目体例使用；不按出现次数判断文风或作者。 |
| 括号 | 保留必要的来源、首释、单位或限制条件。形式上是补注，不代表内容可以无损删除。 |

中文正文通常采用相应中文标点，具体以既有体例和任务为准。示例：“我们核对了接线、量程和采样率；探头偏置仍待验证。”分号保留了两项工作的层次，不需要改为同构排比。

若需要严格标准核对，再查项目适用版本的《标点符号用法》等原文；本参考不声称已经按标准逐条审定。历史媒体频率观察不作为现行硬判据。

# 语序 · 英文句法残留诊断

> 本地适用规则：以下表达模式、频率、年份和人物示例只作风格参考，不证明作者身份，也不代表已核实的当前统计。按用户授权和目标语体判断；有效表达可以保留，不为满足阈值强改。涉及个人口吻、术语和引语时以入口的内容保护规则为准；没有毛边或打磨报告的配额。

> 本文件是 qu-ai-wei 的 **syntax deep reference**。入口负责授权和内容保护，本文件提供可选的语序检查。示例中的原文不一定错误，需按实际上下文判断。

---

## 现代汉语基本语序特征

- **基本语序是 SVO**,但汉语是**话题优先语言**(topic-prominent),不像英语那样严格主语优先。中文习惯**话题 / 主语前置,状语在动词前**。
- **偏正复句倾向**:传统汉语语法里"偏句在前、主句在后"(`因为 X,所以 Y`;`如果 X,就 Y`)。但现代汉语受欧化影响,结果 / 原因语序已较灵活(`他今天没来,因为病了` 完全自然),不是硬性规则。
- **汉语缺乏印欧语式的屈折变化**,但并非"没有形态":名词有词缀(子 / 儿 / 头)、重叠(AA / AABB);动词有体貌标记(着 / 了 / 过)、重叠表尝试(看看 / 试试)。只是没有英文那样的**屈折变化**(case / gender / person / tense)。硬把英文形态特征套到中文上,是最显眼的翻译腔。
- **不完全主谓句是常态**:主语可以靠上下文承前或蒙后省略,不必每句补齐。英文训练的模型倾向把"它 / 他们 / 她"明确写出来,反而不自然(见模式 #33 + #36)。
- **助词分工**:`的`(名词性定语)/ `地`(动词性状语)/ `得`(补语)各司其职,不可混用。AI 输出偶尔会把 `的` 用到状语位置(`慢的走过来` → `慢慢地走过来`)。

---

## 常见英文式语序病

1. **介词短语 / 与-字结构开头过长**
   - ❌ `与运行时、缓存机制、并发模型等性能相关的细节,都交给引擎自己处理` ← 英文 `Regarding X, Y is handled by Z`
   - ✅ `运行时、缓存机制、并发模型这些性能细节,都交给引擎自己处理`(主语前置)

2. **"作为一个 X,..." 开头(语体敏感)**
   - "作为" 是汉语合法的介词,介词短语作状语前置在汉语里完全合规。**不是所有 "作为一个 X" 都是 AI 腔。**
   - **学术论文、社论、评论、演讲里**庄重合法:"作为中国人,我深感..."、"作为一种理论假设,本文..." → 保留。
   - **日常对话、朋友圈、工作邮件、商务文案里**硬套就刺眼:"作为一个产品经理,我认为..." → 改成 "从产品经理的角度看..." 或直接去掉("我觉得...")。
   - **判定标准**:看语体是否跟"作为"的庄重度匹配。匹配保留,不匹配才改。

3. **定语堆叠(语序层面的"的的不休")**
   - ❌ `一个被公认为是行业先驱的、来自硅谷的、拥有多项专利的创业公司`
   - ✅ `一家硅谷创业公司,业内公认的先驱,手里攥着好几项专利`(长定语拆成并列小句)

4. **条件 / 原因从句后置(弱化规则)**
   - 传统汉语偏好"偏句在前"(`如果 X,Y`;`因为 X,Y`),但现代汉语受欧化影响,结果 / 原因后置 **已经非常普遍**:"他今天没来,因为病了" 完全自然。
   - **这条不作为独立 AI 腔规则**,仅当它和**其他英式句法标志一起出现**(长介词短语前置、被动语态堆叠、代词不省略)时,才作为辅助证据。
   - 例:`我不会用这个工具,如果它不支持简体中文的话` ← 这里是"如果...的话"这种冗余的英式条件结构让它刺眼,不是后置本身。可改为 `如果不支持简体中文,我不会用这个工具。`

5. **英文关系从句直译成"的"字句**
   - ❌ `这是一个关于我们如何去除 AI 写作痕迹的故事` ← `a story about how we ...`
   - ✅ `这个故事讲的是我们怎么去掉 AI 写作痕迹`(topic-comment 结构)

6. **状语位置颠倒**
   - ❌ `我们讨论了这个问题在会议上` ← `... in the meeting`
   - ✅ `我们在会议上讨论了这个问题`(时间 / 地点 / 方式状语在动词前)

7. **"令人 / 让人 + 形容词"从英文 make + feel 硬翻**
   - ❌ `这个结果令人感到意外` ← `The result makes one feel surprised`
   - ✅ `这个结果让人意外`（不改变意外的程度；原句也可保留）

8. **英文式破折号插入**
   - ❌ `这个工具很好用 — 除了偶尔卡顿` ← `X — except Y`
   - ✅ `这个工具很好用,就是偶尔会卡顿。`(改用逗号)；保留“除了”所表示的例外关系。

9. **"What...is..." 强调句直译**
   - ❌ `我所关心的是质量` ← `What I care about is quality`
   - ✅ `我在意的是质量`

10. **被动语态密度过高**
    - 见模式 #33。中文被动用得比英文少很多,强行加 `被`、`由`、`受到` 会有翻译腔。

# 品牌文案的任务边界

先按用户指定的发布场景和品牌规范处理。主视觉短句、产品说明、年报、社交推文和客服消息需要的语体不同；不要因为属于同一品牌就统一成短句或第二人称。已有信息足够时直接执行，不重复确认。

## 保留与修改

保留准确产品名、型号、规格、适用条件、限制和必要声明。短句、排比、留白、emoji、第一人称都由场景决定，不设字数或词频门槛。没有依据的“更快、更省电、行业第一”等比较不能靠润色补入；不把产品名或技术译名一律改成英文。

宣传文案中的来源与技术承诺同样需要依据。品牌自身不是让未证实主张成立的理由。用户只要求润色时，不扩成品牌策划或增加产品功能。

## 合成对照

以下只是示例，不是真实广告引文或模型评测：

原文：“这款设备重 180 g，为您的日常携带提供了便利，让您在出门时轻松将它放入背包。”

可改：“180 g，日常出门可放入背包携带。”

保留重量与用途，没有增加续航、性能或防护能力。

原文：“感谢你参加周末试跑。欢迎把试跑感受告诉我们。”

可以原样保留。号召语符合活动用途，不需要为了去 AI 味强改。

## 参考与交付

用户给定品牌样本时，用其可观察的语体和术语习惯作对照，不推定所有品牌共用一套语言。上游 Apple/Nike 示例的来源背景仍在历史备份与来源材料中；不能用名称替代实际读取的规范或已核实产品事实。

默认交付终稿。只有用户要求摘要/报告时才附真实改动；不输出作者身份判断或固定打磨流程。

# 正面参考模型

> 本地适用规则：以下表达模式、频率、年份和人物示例只作风格参考，不证明作者身份，也不代表已核实的当前统计。按用户授权和目标语体判断；有效表达可以保留，不为满足阈值强改。涉及个人口吻、术语和引语时以入口的内容保护规则为准；没有毛边或打磨报告的配额。

> 本文件是 qu-ai-wei 的 **reference models**。用作**反向诊断**而非风格模仿 —— 让 LLM "按三联风格写"通常只会产出刻板仿作。需要语体对照时读取本文件。
>
> **品牌广告 / 文案语体的任务边界与合成示例,见 [brand-voice.md](brand-voice.md),不在本文件。**

去掉 AI 腔只是一半；改写要落在读者熟悉的语域里。以下是几组**正面参考模型** — 但注意：**它们用作"对照诊断",不用作"风格模仿"**。

> ⚠️ 让 LLM "按三联风格写"之类的指令，通常只会产出刻板的仿作。本 skill 用这些名字来做**反向对照**（"这句话放进《三联生活周刊》会不会显得突兀？"），而不是作为模仿目标。

## 长读 · 长篇新闻与随笔（书面，有文学味，人的节奏）

- **《三联生活周刊》** — 现代中文书面语的基准：不僵硬、不花哨，具体、观察、像人。
- **《读者》** — 大众随笔/短文的基准，情感落地，抽象密度低。
- **《中国国家地理》** — 科学/自然/旅行长文，地名准确，不花哨 — 是"璀璨画卷"那种写景套话的反面教材。
- **《财新周刊》** — 财经/政策长文，克制、严谨。
- **《南方周末》** — 深度调查，句长节奏自然起伏。
- **《人物》杂志 / GQ 报道** — 叙事非虚构，场景细节密，抽象密度低。
- **《体坛周报》** — 体育长文 / 赛事评论的基准。遇到体育语境时用作对照（专有名词约定、惯用术语、叙事节奏都在这本里有参考）。

## 日常 · 产品/UX 白话（短句，接地气）

- **微信 UX 语言** — 所有简体中文用户每天都在看：通知、空状态、设置。短、中性、没有 emoji、没有"赋能/助力"、没有"让我们一起"。比如 `发送中...`、`网络未连接,请检查后重试`、`此消息已撤回`。
- **微信读书 UX** — 内容阅读类产品的同类语域。
- **小红书 笔记（非推广）** — 个人化、口语、第一人称，适合随笔语域。
- **豆瓣 长评** — 有想法但不装，个人声音强。

## 文学 · 文学散文（节奏与具体感）

扩展锚点集，覆盖平实/抒情/京味/南方/反思等语域。实际改写中按输入原文的语域挑最接近的文学对照。

- **汪曾祺 散文** — 短句、具体名词、没有修饰堆叠。`璀璨画卷`修辞的解毒剂。
- **阿城《棋王》《树王》《孩子王》** — 极简，几乎没有填充词，名词动词驱动。
- **沈从文《边城》《湘行散记》** — 抒情但具体，有地方感，不花哨。
- **老舍《骆驼祥子》《茶馆》** — 京味儿白话，幽默，有人物声口。
- **鲁迅 杂文 / 钱钟书《围城》** — ⚠️ **谨慎参考**。两人文字都有**有意的欧化倾向**（鲁迅五四早期白话实验，钱钟书大量西式长句与典故嵌套）。他们**不适合作为"去 AI 腔"的直接锚点** —— 强行模仿反而会学出"学者腔""文人腔",比 AI 腔更难祛除。只在**锋利度、密度、思辨强度**上借鉴，不在**日常白话自然度**上对照。
- **张爱玲《流言》《红玫瑰与白玫瑰》** — 细节具体，氛围感强。
- **余华《活着》《许三观卖血记》** — 平实、有力，没有修饰膨胀。
- **史铁生《我与地坛》《命若琴弦》** — 反思性散文，立足观察。
- **朱自清《背影》《荷塘月色》** — 经典，清晰，情感诚实。
- **林语堂 散文** — 机智，双语感，反掉书袋。
- **木心《文学回忆录》《素履之往》** — 格言式，压缩度高。
- **王小波 杂文** — 反讽，反装腔，聪明而好玩。
- **梁文道 / 唐诺 随笔** — 有文化密度，不堆辞藻。
- **贾平凹 散文 / 迟子建 散文** — 秦地 / 东北方言感，地域具体。

## 公文 / 学术 / 法律 语体锚点

去 AI 腔 **不等于** 把所有文本降级到日常白话。正式语体有自己必须的写法 —— 当文本属于这些语体时，**不应套用"日常自然"的标准**。

**公文 / 政论：**
- 《国务院公报》— 现行政府公文语体范本
- 《人民日报》社论 — 政论体权威
- 《最高人民法院公报》— 司法公文的精确度范本

**学术 / 科技：**
- 《中国社会科学》《经济研究》《中国科学》系列期刊 — 一流学术语体
- 商务印书馆《现代汉语八百词》（吕叔湘）、《语法讲义》（朱德熙）— 语法学权威著作本身就是学术语体范本

**法律文本：**
- 《中华人民共和国民法典》《刑法》— 法律语言的精确度标准
- 《最高人民法院指导性案例》— 司法文书范本

**怎么用：** 同样作"反向诊断"而非"风格模仿"。改写前问："如果这段文字出现在这类正式文本里，会突兀吗？"会突兀 → 这个改写方向错了，退回来。

## 怎么用这些参考

按原文用途和用户指定语体选择对照。技术报告采用准确、克制的书面表达；个人叙述可保留已有口吻。不要因为句子放进某本杂志不合适，就判定它是 AI 文本。

这些名称提供语域线索，不构成已读取相应原文的证据，也不要求模仿作者。缺少风格样本时保持原文合适的语体；只有目标确实不明确并影响改写时才澄清。

# 按授权交付的示例

## 阅读方式

以下是说明行为边界的合成示例，不是真实模型评测结果。输出形式由用户任务决定，不统一要求初稿、自审或打磨报告。

## 正式技术表达

请求：润色这句话，只要终稿。

原文：本次测试过程中对 ADC 输入端的等效噪声进行了相应的测量，结果为 2.3 mV RMS，采样率 1 MS/s，测量带宽 100 kHz，目前尚未扣除仪器底噪。

改后：本次测得 ADC 输入端等效噪声为 2.3 mV RMS，采样率为 1 MS/s，测量带宽为 100 kHz；结果尚未扣除仪器底噪。

保留数值、单位和未校正条件，不增加“达标”“板卡噪声已确认”等结论。

## 已授权的个人文字

请求：这是我写的，帮我去掉重复，保留原来的语气。

原文：昨天我又试了一遍，试完还是没想明白。我说不上来哪里不对，就是觉得这里不太对。

改后：昨天我又试了一遍，还是没想明白。我说不上来哪里不对。

完成授权修改，保留犹疑，不因“是我写的”拒绝，也不添加经历。

## 仅审查

请求：只指出问题，不改写。

原文：这项工作具有十分重要的重大意义，有力地提升了能力。

合适回应：指出“十分重要的重大意义”重复，以及“能力”指代不明；不直接输出整段替换稿。

## 局部代码说明

请求：只润色注释，保留代码。

```verilog
// 对当前计数值进行一次增加操作
count <= count + 1'b1;
```

可改为：

```verilog
// 计数值加 1
count <= count + 1'b1;
```

不引入使能、复位或延迟含义，不改可执行语句。

## 保留有效表达

“基于当前模型进行仿真”在技术说明里可以直接使用。不要为了降低“基于”“进行”的比例改成生硬的口语。用户指定引语保持原样时，句长、重复和标点偏好都不能成为改动理由。

## 原有参考归属

- 叶圣陶的写作主张、叶圣陶与夏丏尊《文心》：表达自己的意思，避免空话。书目、引语原文和版本需要引用时另查，不把历史摘录作为已核实引语。
- 吕叔湘《现代汉语八百词》、朱德熙《语法讲义》：汉语语法与用词参考。
- 《标点符号用法》GB/T 15834-2011：原技能列出的标点参考，严格任务按项目适用版本查证。
- [Wikipedia: Signs of AI writing](https://en.wikipedia.org/wiki/Wikipedia:Signs_of_AI_writing) 与 [WikiProject AI Cleanup](https://en.wikipedia.org/wiki/Wikipedia:WikiProject_AI_Cleanup)：上游通用表达模式来源。
- [维基百科：AI生成文的特徵](https://zh.wikipedia.org/wiki/Wikipedia:AI%E7%94%9F%E6%88%90%E6%96%87%E7%9A%84%E7%89%B9%E5%BE%B5)：中文社群观察。
- [yage.ai《写作中的 AI 味是哪儿来的》](https://yage.ai/share/ai-chinese-translationese-20260418.html)：原技能 #39—#42 的观察来源。
- 《咬文嚼字》的流行语及语文差错观察：可按需要核对语言使用，未入榜、旧词或新词都不能证明作者身份。不再维护强制替换的“已入土词”表。

## 语料核查

[北京大学 CCL](https://corpus.pku.edu.cn/)（原技能还列有旧入口 http://ccl.pku.edu.cn:8080/ccl_corpus/）和北京语言大学 BCC 可在难以判断搭配时提供材料。先确认当次可用入口和检索范围；记录语料年代、语体及查询。频率只能提供用法线索，低频不等于错误，更不能覆盖用户语体或领域术语。

上游已声明其规则并非逐条通过语料库验证。本轮也未做全面语料调查。未来依据真实问题更新具体参考时，记录证据并重建 flat 文件；不要按固定年份批量替换正文词汇。
