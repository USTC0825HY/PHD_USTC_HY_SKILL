# Mermaid Rendering Rules

适用范围：`Laser_PDH_Study` 全局 Mermaid 产出（当前以 flowchart 为主）。

## Mermaid 内容约束

- 跨板图每块物理板一个subgraph，浅色底纹在全文一致，并保留板名；长网名及参数放节点对照表。
- 跨板图默认TB、板内短图LR；若跨节点连线使子图方向失效，可连接分区ID，并把必要接口关系列在节点表，不能为布局隐藏真实分叉。检查最长路径是否穿过分区标题。
- 实线表示已核对的设计路径；未知配对用标明缺口的虚线，TSD未选支路不得画成有效通路。图示方向是追踪方向时应明确说明。

- 不要在 Mermaid 节点文本中使用 `/n`、`\n`、`<br/>`，这些会导致 Obsidian 与浏览器预览异常。
- Mermaid 节点标签建议不超过 12 个字符。
  - 长内容放在 Markdown 正文、表格或图下说明。
  - 图内只保留“结构名/关键动作名”，不写长清单、器件参数、网络名集合。
- 不要在图内塞长指标、长测试条件、器件清单或网络名集合；这些信息必须放在正文、表格或图下注释中。
- 避免在图中混入大量测试/调试文本，优先用外部注释或链接说明。

## 交付格式（强制）

- 正式 Markdown 中必须至少内嵌一个可直接渲染的 `mermaid` 代码块，不能只放 `.mmd/.html` 跳转链接。
  - 单图正文：内嵌正文对应图。
  - 多图索引/导航：默认内嵌总览或代表图；明确要求每一路内嵌时遵守要求，用章节折叠管理阅读。
- 每张图必须有一套独立配对文件：
  - `<name>.mmd`：纯 Mermaid 源文件
  - `<name>.html`：独立查看页（zoom/pan）
- 同名 `.html` 内仅绑定一段源文本，不共用多个 `.mmd` 源，避免不同图互相干扰。
- 相关 Markdown 中必须同时提供 `.mmd` 图源链接和 `.html` 缩放查看入口。
- HTML 工具栏应包含：
  - 放大
  - 缩小
  - 重置
  - `.mmd` 源文件打开入口
- HTML 页面应展示源码预览，便于独立调试。
- 每个 HTML viewer 只调试一张图，图与图之间不共享源码块或状态。

## 缺陷判定（audit 期望为 0）

- Mermaid 源文本包含 `/n`、`\n`、`<br/>`。
- 节点标签长度过长（默认阈值：12 字符）。
- 同名 `.mmd` 与 `.html` 不成对存在。
- `.html` 中未采用单图源码渲染或源码链接不是同名文件。
- Markdown 中声明的本地 `.mmd/.html` 目标不存在。
- 正式 Markdown 只有 Mermaid 资源链接、没有任何内嵌 `mermaid` 代码块。

`01_Raw` 中的原始聊天导出或源材料允许保留原始 Mermaid 标签长度；正式笔记、项目文档和 `_mermaid/*.mmd` 必须遵守节点长度约束。

## 备注

资源可位于本笔记专用目录，不要求目录名为`_mermaid`。审计根据实际链接发现资源，核对正文、mmd与HTML源码一致；查看器检查功能和依赖，不要求固定JS/CSS文件名。静态检查不能代替运行渲染或缩放操作测试。不要把整套浏览器／运行时复制进笔记库。

遇到复杂跨图注释时，优先拆图而不是加长节点文本。
