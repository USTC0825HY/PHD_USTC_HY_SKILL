# 简洁、时序可控的手写 RTL

## 先确定行为，再写代码

- 沿用目标工程的 HDL、工具版本和命名。不得仅为风格将 Verilog 升级为 SystemVerilog。
- 明确时钟/频率、复位、位宽/符号、请求接受条件、数据有效时刻、延迟、吞吐、背压及启动/停止语义。小模块用短说明，不强制大表格和架构图。
- 简化默认保持端口、参数语义与逐拍行为；改变流水线、采样边沿、握手、完整帧停止或对外模块边界时说明影响。用户已明确要求的改变不重复请求授权；超出原请求的改变先确认。

## 结构与表达

- 控制状态和寄存器有明确写入责任；保留有意义的器件、协议和时钟域边界。
- 每个模块、状态、寄存器、参数和握手必须服务真实功能、必要复用或时序要求。不为单用途建立通用总线、多层包装、可插拔框架和未使用模式。
- FSM 不强制三段式、独热或固定状态数；以输出时序和易读性选择。不要为匹配模板引入无用中间状态。
- 默认一文件一主要模块，按功能文件夹组织。不得为了让 GUI 层次像目录树而增加包装模块。common 只收真实共享且语义一致的模块。
- 每个端口、信号声明、实例连接和赋值各占一行，四空格缩进，适度对齐。命名说明功能；注释解释原因、单位、边界或协议，不复述语句，不堆装饰标题和“灵活健壮”等空泛描述。
- 拆分声明保留位宽、signed、初始化与属性范围；纯排版不改表达式、名称、端口顺序或时序。冻结原生、第三方及生成文件不因风格被重写。
- 不用代码行数、模块数或寄存器数作为成功标准。“去 AI 味”不是删除必要注释、CDC、握手、FIFO或流水线。

## 时序敏感检查

- 审查加减乘移位的中间位宽/符号、截断/饱和/回绕约定、计数终值、零/极值与参数边界。
- 查长组合运算、优先级链、大 mux、高扇出控制。只有证据支持才提出流水线/复制/编码修改；不靠风格推断时序已改善。
- 不统一增加或删除所有数据寄存器复位。根据有效性、启动行为、安全输出和资源推断需要决定。
- 对多位跨域配置保证一致性，对脉冲保证事件传递，对复位检查各域释放；不能把每位独立同步当成总线一致性协议。
- 不为通过报告降低既定频率、添加无依据 false/multicycle path 或滥用 KEEP/DONT_TOUCH。必要例外须有具体路径和功能理由。

## 最小验证

- 使用独立预期值/模型或修改前后逐拍比较；测试正常、边界、连续请求、忙时请求、背压、复位中断、停止/重新启动及适用的溢出情况。
- TB 必须有实际检查、明确 PASS/FAIL 和超时；故意错误应能导致失败。仿真结束或编译通过不等于功能通过。
- 代码整理保持语义时，使用差异审查及适当编译/等价验证；报告剩余盲区。
- 静态、仿真、综合估计、布线后时序和板测分开报告。未运行的阶段不自动触发、不声称通过。
